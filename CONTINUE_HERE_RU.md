## Git при смене компьютера

Ветка — `main`, upstream — `origin/main`. В чистом рабочем дереве:

```powershell
git status --short --branch
git fetch --prune origin
git pull --ff-only
```

Если есть локальные изменения или ветки разошлись, сначала разобраться в обеих сторонах. Не применять `reset --hard`, `git clean` или force push для синхронизации. Законченные изменения коммитить и отправлять обычным `git push origin main`; автор и коммитер — **Joe6355 <Dudin1918@mail.ru>**. Статус CI смотреть для конкретного нового SHA.

APK распространяются через Releases. Ключи подписи, `keystore.properties`, `local.properties`, фотографии и локальные артефакты в Git не добавлять. Файлы из игнорируемой `artifacts/` на ноутбуке не появятся на ПК после `git pull`; переносимый итог находится в этом файле, отчётах репозитория и Release.

После каждого законченного блока обновлять эту точку продолжения: что сделано, что проверено, на каком APK/устройстве и какой шаг следующий. Подробные результаты сохранять в датированном отчёте или чек-листе и оставлять здесь ссылку. Закрытый сценарий возвращать в работу только с указанием новой причины; перед сменой компьютера отправлять обновлённые документы в `main` вместе с завершёнными изменениями.
