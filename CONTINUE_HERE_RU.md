## Уже завершено — повторять без причины не нужно

- Исправления полноразмерного просмотрщика, сохранения редактора, диапазона ISO, ошибок записи JPEG/ZIP/MP4, восстановления checkpoint и конфликтующих файловых операций выполнены и описаны в отчётах чек-листа.
- На **основной beta.4** доступны низкие ISO; четыре настоящих JPEG независимо декодированы: 1440×1920, EXIF ISO400 / 1/30 с.
- Пройден один свежий сценарий: один одиночный JPEG + серия 3/3 → один собственный кадр «Брак» → Average по трём кадрам / OFF → полноразмерный Edited PNG → переименование, отмена удаления и подтверждённое удаление собственного результата.
- ZIP: 16 записей, корректные CRC, шесть изображений совпали по SHA-256, сведения и отметки подтверждены. MP4: все три кадра 1080×1440 / 5 кадр/с последовательно декодированы до EOS.
- Пять прежних контрольных серий открыты при 100%; настоящий JPEG4096×3073 открылся в редакторе. Основные действия обработки, просмотрщика и редактора доступны в красной теме при шрифте 200%. Значок, системная заставка и холодный запуск проверены.
- Все **1772 прежних общих файла**, **222 legacy-private** и **615 QA-private файла** побайтно прежние. Добавлены только семь собственных файлов, итог — 1779 общих. Подробности и границы проверки private main — в отчёте приёмки.
- Подписанный кандидат уже получен с ПК и установлен. Для повторного скачивания есть Release; заново просить владельца принести этот APK или ключ ради закрытых проверок не нужно.

Повторять затронутую проверку следует после изменения соответствующего кода, нового воспроизведённого дефекта или проверки другого устройства. Полный проход старых астрономических серий без новой причины не начинать.

## Что делать следующим

1. **Другой телефон:** установить готовый APK, записать модель/Android, проверить запуск, разрешения и короткую JPEG-серию. Это новая проверка совместимости, а не повтор прежнего телефона.
2. **Реальное небо:** получить одну закреплённую серию с заметными звёздами; сравнить одиночный кадр и результат при одинаковом масштабе. Проверить фактическую выдержку и фокус. Для проверки dark frames объектив нужно действительно закрыть.
3. По обратной связи исправлять конкретные ошибки. Для каждой — устройство, версия/APK, шаги, ожидаемое и фактическое поведение, результат повтора после исправления.

Остаются открытыми физический фокус и предпросмотр на содержательной сцене, отдельные условия длинной выдержки, звук/вибрация, ETA и ресурсные крайние случаи, другие Android/камеры и косметика крупного шрифта. Совмещение, сложный фон и слабые детали имеют известные ограничения; универсальное качество не заявлено.

## Git при смене компьютера

Ветка — `main`, upstream — `origin/main`. В чистом рабочем дереве:

```powershell
git status --short --branch
git fetch --prune origin
git pull --ff-only
```

Если есть локальные изменения или ветки разошлись, сначала разобраться в обеих сторонах. Не применять `reset --hard`, `git clean` или force push для синхронизации. Законченные изменения коммитить и отправлять обычным `git push origin main`; автор и коммитер — **Joe6355 <Dudin1918@mail.ru>**. Статус CI смотреть для конкретного нового SHA.

APK распространяются через Releases. Ключи подписи, `keystore.properties`, `local.properties`, фотографии и локальные артефакты в Git не добавлять. Файлы из игнорируемой `artifacts/` на ноутбуке не появятся на ПК после `git pull`; переносимый итог находится в этом файле, отчётах репозитория и Release.

После каждого законченного блока обновлять эту точку продолжения: что сделано, что проверено, на каком APK/устройстве и какой шаг следующий. Подробные результаты сохранять в датированном отчёте или чек-листе и оставлять здесь ссылку. Закрытый сценарий возвращать в работу только с указанием новой причины; перед сменой компьютера отправлять обновлённые документы в `main` вместе с завершёнными изменениями.
