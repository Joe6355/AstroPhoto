# Исправление двух ночных серий из окна — 04.11.2026

## Область и текущее состояние

После [первичного разбора](window-night-review-2026-11-04.md) владелец разрешил исправлять конкретные дефекты этих новых серий. Это целевое изменение ранее замороженного JPEG-конвейера; RAW, публикация и старые аппаратные сценарии в работу не возвращались.

Код подготовлен, **75 целевых JVM-проверок прошли без ошибок**. На момент первой записи этого отчёта выполняется окончательная проверка двух наборов в отдельной QA. Результаты промежуточных кандидатов ниже не означают приёмку окончательного APK. Итог телефона, сохранность и CI будут добавлены после завершения.

Вход: `Session_20261104_000226_новая_серия_1_окно` — 30 JPEG; `Session_20261104_002805_новая_серия_2_окно` — 10 JPEG. Все 40 исходников 1440×1920 сняты через закрытое стекло. Используются частные копии QA, оригиналы основного приложения не являются выходным каталогом.

## Доказанная причина

Полный Android-прогон прежнего кода на второй серии воспроизвёл **байт-в-байт тот же PNG**, что сохранился у владельца: опорный кадр5, использованы5/8/9/10, `PROCESSED`, прежняя проверка приняла результат. Это воспроизводимый дефект конвейера, а не только отображения Галереи.

Снимки линейного RGB16 между этапами показали:

- До проявления фона крупная структура неба сохраняется. После нелинейного осветления и глобального согласования одного среднего уровня становятся заметны очертания маски.
- В уменьшенном анализе яркие детали домов занимают ограниченный каталог. Слабые движущиеся звёзды теряются из-за абсолютного порога контраста; регистрация выбирает почти неподвижное объяснение.
- После восстановления звёзд выяснилось, что обычный допуск поворота требует12 соответствий. Для редкого поля есть измеренные звёзды, но слишком мало для этой общей ветки.
- В первой серии проявилась отдельная ошибка проверки покрытия: отсутствующие клетки слева/справа сравнивались как нули. На промежуточном стеке покрытие внутренних проверяемых областей было0,99999988–0,99999994, но оценка равномерности получалась0. Сравнивались0/23 занятых клеток слева/справа и6/0 сверху/снизу.

## Изменения

1. `ProfileFrameAnalysisCoordinator` применяет существующее уточнение маски для отбора признаков. Исходная грубая маска сохраняется для пиксельной интеграции и последующего штатного уточнения; повторное сужение области обработки исключено. В локальном детекторе порог слабой PSF снижен с6 до3 кодовых значений, при сохранении требований локального шума, формы и отсечения дефектов.
2. `ProjectiveStarRegistrar` получил ограниченную ветку поворота с фиксированным объективом для редкого поля. Нужны данные объектива из EXIF, минимум3 согласованных движущихся трека и минимум4 независимых полноразмерных источника. Каждый источник проверяется вне своей подгонки; остаются пределы ошибки0,35/0,60px, физические ограничения матрицы, фотометрия и проверки размытия. Свободная гомография сохраняет прежние требования; произвольное принятие отклонённых кадров не добавлялось.
3. `SkyBackgroundToneMatcher` согласует добавленное осветление по локальным робастным оценкам RGB16. Область вне маски сохраняется. Защищены реальные тёмные детали; кеш строк подстраивается под бюджет памяти. У операции есть отмена и учёт памяти.
4. В `CoverageUniformityValidator` градиент сравнивает занятые клетки одного и того же ряда/столбца. Проверки настоящих внутренних провалов покрытия сохранены.
5. `BackgroundQualityComparator` проверяет новый перепад фона по мягкой маске. `LineArtifactDetector` отклоняет одиночный длинный след, включая диагональный. Прежний PNG второй серии теперь отклоняется обеими проверками.
6. Обновлены версии checkpoint анализа, регистрации и интеграции/постобработки, чтобы не восстанавливать старые производные расчёты.

Главные файлы: [анализ](../app/src/main/java/com/joe6355/astrophoto/ProfileFrameAnalysisCoordinator.kt), [редкое поле](../app/src/main/java/com/joe6355/astrophoto/processing/jpeg/v2/registration/ProjectiveStarRegistrar.kt), [фон](../app/src/main/java/com/joe6355/astrophoto/processing/jpeg/v2/postprocessing/SkyBackgroundToneMatcher.kt), [покрытие](../app/src/main/java/com/joe6355/astrophoto/processing/jpeg/v2/quality/CoverageUniformityValidator.kt), [контроль маски](../app/src/main/java/com/joe6355/astrophoto/processing/jpeg/v2/quality/BackgroundQualityComparator.kt), [контроль следов](../app/src/main/java/com/joe6355/astrophoto/processing/jpeg/v2/quality/LineArtifactDetector.kt).

## Проверки и ограничения

Окончательные целевые проверки:75 выполнены,0 ошибок/падений/пропусков. Включены физическая геометрия и независимые источники, тени RGB16,512KiB рабочего бюджета, побитовая независимость от размера плитки, маска/foreground, покрытие и следы.

Первый широкий локальный прогон обнаружил4 падения среди1386 тестов: затемнение слабой положительной подложки, фиксированный слишком большой кеш и два недетерминированных тестовых снимка занятой JVM-памяти. Исправлены операция и тестовые бюджеты. Старый RGB16-прогон также приведён к фактическому пути приложения: сохранение источников и проверка6 независимо подтверждённых позиций из fixture вместо недостаточного глобального каталога. Пороги качества не ослаблялись. Полный повтор для окончательного кода ещё должен быть сверён по конкретному SHA CI.

Промежуточные Android-кандидаты уже дали принятые результаты: вторая серия4/10 с опорным9 и первая12/30 с опорным27, без принудительного согласия на недостаточные кадры. У второй серии контрольные предсказания геометрии дали P90 до0,489px. Затем отдельно исправлены защита теней/память и сохранение исходной области маски; поэтому окончательный APK проверяется заново на обеих сериях.
