# Точность проверки цвета усиленного изображения — 19.10.2026

## Причина отказа

После исправления совмещения `035444` сохраняла чистый стек, но Enhanced с gain 0,4 всё ещё отклонялся по `new_strong_color_patch`. В неизменённых копиях промежуточных буферов найдена связная группа из четырёх проверяемых отсчётов. Цвет измерялся после преобразования RGB16 → RGB8 → линейный RGB, хотя обработка работала с RGB16.

Пример реальных отсчётов: `[50,50,88] → [64,64,113]` в линейных 16-битных каналах. Изменение долей каналов около 0,0008. После округления отображаемые значения `[3,3,4] → [3,3,6]` дают изменение 0,10; округление также переводит исходный сигнал через минимальный порог 0,003. Проверка объявляла это новым сильным цветным пятном. Независимый расчёт на копиях всех трёх буферов усиления не нашёл сильных связных изменений в исходном RGB16; для итогового gain 0,4 группа в RGB8 подтверждается.

## Изменение

Основная проверка цветовых долей читает линейные отсчёты из источника с его рабочей точностью. Для ARGB8-источника адаптер по-прежнему измеряет его реальные декодированные значения: сдвиг цвета в самих исходных RGB8 не освобождается от проверки.

Сохранены пороги сдвига 0,08, минимального сигнала 0,003, связного размера четыре отсчёта, восемь соседей, маска неба и исключения вокруг подтверждённых звёзд. Реальное сильное изменение цвета в RGB16 остаётся причиной отказа. Отдельно считается эффект только отображаемого округления: `quantizationOnlyColorPatchCount` и предупреждение `color_patch_within_output_quantization`. Метрика `colorPatchMeasurementLinear16=1` явно указывает способ измерения; `newStrongColorPatchCount` теперь относится к линейным рабочим отсчётам.

Выходной PNG остаётся 8-битным. Исправление не обещает устранения всех цветовых ступеней его отображения: наблюдение об округлении сохраняется в отчёте. Проверки полос, фона, потери/ослабления звёзд, клиппинга, линий и формы не отключаются.

Тест полностью небесного кадра выявил ещё один ложный отказ того же валидатора: при отсутствии пригодных границ переднего плана доли сохранения и согласия знака были 0/1. Теперь при нуле измеренных границ обе равны 1, как уже делалось для косинусного сходства. Это не разрешает потерю существующих границ: отдельный тест с удалённой границей получает 0 и отказ `foreground_edge_geometry_changed`.

Дополнительно декодированный новый Enhanced побайтно по всем RGB8-пикселям совпал с отображаемым представлением ранее сохранённого и отклонённого RGB16-кандидата gain 0,4. Соответствие базового буфера опубликованному чистому PNG и его display-хэшу тоже подтверждено. Это исправление способа проверки и допуска, а не изменение генерации изображения; файл остаётся RGB8. Доказательство — `buffer-publication-proof.json`.

В 100 одинаковых окнах независимого детектора относительно отдельно сохранённого чистого PNG медиана отношения пиков — 1,239, P10 — 1,043; медиана отношения ширин — 1,073, сдвига центра — 0,055 пикселя. Эти измерения в кодовых значениях не являются калиброванной фотометрией; увеличение отображаемой ширины нельзя выдавать за улучшение резкости или всех слабых деталей. Чистый PNG доступен отдельно.
