# Цельные надписи выбора вариантов при крупном шрифте

01.11.2026, ноутбук; работа начата31.10 поверх `67ea8c5`. Закрыт конкретный дефект из [проверки крупного шрифта](night-font-acceptance-2026-10-30.md).

## Изменение

Общий `AstroSegmentedControl` делил ширину между всеми вариантами в одной строке и ограничивал подпись двумя строками. При200% «Светлая» превращалась в «Свет/лая», «Красная» — в «Крас/ная», а часть «Очень тёмная» исчезала.

Теперь компонент измеряет минимальную ширину целого слова с текущим шрифтом и распределяет варианты по сбалансированным рядам. Четыре темы на узком экране при крупном шрифте становятся **2×2**, при обычном остаются в строке. Ограничение двумя строками снято, текст центрируется, высоты соседних вариантов выровнены. Существующие обработчики, radio-семантика, выбор и блокировка действий сохранены. Изменён один производственный файл: `ui/AstroComponents.kt`; алгоритмы обработки и настройки камеры прежние.

## Проверка

Xiaomi 23021RAA2Y, Android13, отдельная QA beta.5/code6. Новый opt-in [Android-тест](../app/src/androidTest/java/com/joe6355/astrophoto/SegmentedControlFontDeviceTest.kt) проверяет настоящий компонент:

- **До исправления:** при200%/320dp и200%/240dp воспроизведены разделение слов и потеря текста; обычный100%/360dp прошёл. Два ожидаемых отказа из трёх, **9,381с**.
- **После:** те же три случая прошли за **11,084с**. Ни одна подпись не разрезана внутри слова и не обрезана. Во всех случаях нажаты все четыре варианта: callback один раз на нажатие, выбран только нужный вариант.
- **Настоящие настройки:** системный шрифт временно200%, через «Интерфейс» выбрана красная тема; все четыре полные подписи видны в сетке2×2. Нативный снимок просмотрен. Камера, съёмка и обработка не запускались.
- `assembleDebug`, `assembleDebugAndroidTest`, `lintDebug`: **BUILD SUCCESSFUL, 2мин21с**, lint **0ошибок /14предупреждений**. Предупреждения относятся к версиям зависимостей/SDK и прежним незатронутым файлам. Основной release подготавливается отдельно; старый пакет `44c24f7` этой правки не содержит.

Первый диагностический тест ошибочно считал `hasVisualOverflow` коротких обычных подписей дефектом: ширина сохранённого абзаца Compose была199px, а фактический текст129px и помещался. Проверка уточнена до границ нарисованных строк, усечения и разделения слова. Затем **до производственной правки** повторно получены два реальных отказа и один успешный обычный случай. Первоначальные журналы и снимки сохранены, успешными они не объявлены.
