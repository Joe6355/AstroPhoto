# Исправления после device-аудита AstroPhoto

Этот отчёт продолжает `device-audit-2026-09-05.md`. После первоначальной проверки без подключённого устройства телефон был подключён вечером 08.09. Исправления установлены совместимым обновлением без удаления приложения и сессий. Итоги повторной проверки, исправления UI-тестов и продолжение работы 09.09 — в [отчёте продолжения](device-audit-2026-09-09.md).

## Изменения

### Точность обработки и regression gate

- `FileBackedAdaptivePresetProcessor`, `FileBackedSkyStatistics`, `FileBackedSkyForegroundComposer`: файловый ARGB8 сохраняет прежнее округление на этапах; RGB16 сохраняет линейные 16-битные значения. Существующие ARGB8 hash и порог replay ≤ 2 уровня не изменены.
- `LinearRgb16PipelineTest`: композиция сравнивается с независимой формулой линейного смешивания. Допуск — половина 16-битного шага `0.5 / 65535` плюс `1e-7` на float-арифметику. При alpha=0/1 требуется точное совпадение исходных 16-битных значений.
- `LinearRgb16Stage4RegressionTest`: `urban-window-30`, RGB16, разные бюджеты памяти/границы тайлов, побитовое совпадение промежуточного результата, неизменный передний план при alpha=0, отсутствие новых причин отказа существующего quality gate по сравнению с ARGB8.
- Это не утверждение, что всякая серия подходит для Deep Sky: на `urban-window-30` отдельный кандидат Stage 4 DEEP_SKY отклоняется за рост MAD и banding и в ARGB8, и в RGB16. Изолированный replay Stage 4 не равен полному production pipeline.
- Устаревшие структурные тесты ручного стека приведены к единому координатору; добавлена проверка передачи плана и публикации только успешно интегрированных кадров.

### Сведения о сессиях

- Новый `SessionInfoStore` хранит актуальные сведения в `filesDir/session-info`. Запись идёт через временный файл, синхронизацию содержимого и замену; параллельные обновления сериализованы. Legacy `Pictures/.../session_info.txt` остаётся источником для чтения, но новые текстовые файлы через MediaStore в Pictures не создаются.
- Съёмка, стекер, редактор, управление результатами и ZIP используют одно хранилище. Обновление счётчиков съёмки сохраняет историю обработки. ZIP содержит одну актуальную копию `session_info.txt`.
- При переименовании сначала готовятся метаданные, затем перемещаются кадры. При неудаче перемещения выполняется откат. Если откат неполный, сохраняются обе копии сведений и показывается предупреждение, а не обещание полного отката.
- Android 13 также отклонил перемещение JPEG в Pictures через `MediaStore.Files/<id>`. Исправлен выбор Images/Video URI по типу записи, включая откат. Round-trip на тестовых файлах после исправления прошёл.
- Проверка точного префикса пути защищает соседние сессии: `_` в SQL LIKE не должен приводить к их перемещению, удалению или попаданию в ZIP.
- Список сессий повторно не запрашивает legacy sidecar для каждой папки, уже просмотренной при загрузке.
- Ограничение: новые сведения находятся в данных приложения и удаляются при очистке данных/деинсталляции. Для переноса следует экспортировать ZIP. Сами пользовательские кадры этим изменением не перемещаются и не удаляются; переименование/удаление выполняются только по отдельной команде пользователя.

### Интерфейс и камера

- `SessionBrowser`: название карточки ограничено двумя строками, метка «Активная» находится ниже. Добавлен Compose-тест длинного имени при fontScale=1.3.
- `CameraPreviewView`: requested/actual SENSOR_EXPOSURE_TIME, ISO и sensor/image timestamp записываются в диагностику рядом с EXIF. Это позволяет выяснить источник несовпадения 1/60 и 1/50 на устройстве.
- `CameraScreen`: несовпадение выдержки обнаруживается в обе стороны; нулевые/отсутствующие значения не считаются подтверждением ручных настроек. Ошибка записи сведений показывается коротко, подробности остаются в журнале.
- Compose-тесты используют явную debug-only Activity с ограничением времени. Добавлен opt-in `SessionMetadataDeviceTest`: сохранение → повторное чтение → ZIP → переименование → удаление, с контролем соседней QA-сессии и активной пользовательской сессии.
- На MIUI подтверждён запрет фонового запуска test Activity. Общий opt-in `AstroUiForegroundRule` сначала выводит debug-only Activity через shell instrumentation, без изменения разрешений. После исправления состояния панели при свайпе и теста прокрутки LazyColumn прошли 16/16 UI-тестов; metadata round-trip — 1/1. Логи и команды приведены в отчёте 09.09.

## Диагностика `дорога_20`

Добавлен opt-in `LocalSessionRegistrationAuditTest`, который только читает локальную копию первых десяти JPEG. Размер анализа 720×960, как в проверяемом pipeline, но декодер ImageIO, не Android BitmapFactory. SHA-256 исходников проверяется до и после.

Первичная диагностика выбрала кадр 001: 42 найденные звезды, фон 27/255. В остальных девяти кадрах — 2–14 звёзд и фон 2–11/255. StaticArtifactAnalyzer не удалил кандидатов. Выравнивание приняло 1/10, модель `ZERO_OR_UNOBSERVABLE`, причина отказа остальных — `sequence_motion_not_observable`; у них 0–3 совпадения и максимум 2 inliers.

Перебор допустимых опор на локальной копии дал 6/10 для кадра 009: исходники нельзя объявлять непригодными только по первому отказу. 09.09 добавлен повторный выбор опоры при провале первичного выравнивания. На Android декодирование дало другую успешную опору (007), 6 предварительно принятых кадров, затем 4 после full-resolution verification. Проверки приёмки/rotation и quality gate не ослаблялись; подробный результат — в отчёте продолжения.

Запуск диагностики на локальной резервной копии:

```powershell
$env:ASTROPHOTO_QA_SESSION_DIR = 'D:\path\to\session\Lights\JPEG'
.\gradlew.bat :app:testDebugUnitTest --tests '*LocalSessionRegistrationAuditTest' --console=plain
```

Без переменной этот opt-in тест пропускается. Пользовательские JPEG не добавляются в Git.

## Проверки и ограничения

Полный JVM-прогон исходных исправлений повторён 09.09: 1115 тестов, 0 падений/ошибок/пропусков. XML сохранён отдельно в `artifacts/device-qa-20260909/jvm-before-reference-recovery`, чтобы последующие выборочные запуски его не перезаписали. Новый recovery проверяется дополнительно; итог сборки/lint см. в отчёте продолжения.

Команда проверки из корня проекта:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease --console=plain
```

На телефоне остаются: фактические настройки Camera2 после добавления диагностики, обработка через UI/service с поворотом/остановкой через уведомление, сравнительные качество/время/память RGB16. Нехватка места и пределы больших изображений также не считаются проверенными на устройстве. Прямой вызов стекера из instrumentation не проверяет lifecycle UI/service.

Исходные сессии и их резервные копии не изменялись. Изменения этого исправления не отправлены в GitHub.
