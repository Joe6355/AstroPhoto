# Подготовка и подпись beta.5 на ПК

Кандидат: **0.9.0-beta.5 / versionCode 6**, основной пакет **com.joe6355.astrophoto**. Включает исправления счётчика прошедших кадров и понятное сообщение ENOSPC при сложении. Алгоритмы обработки прежние. Опубликованная beta.4 остаётся отдельным проверенным релизом.

## Что сделать на ПК

1. Открыть **PowerShell 7** в папке своего проекта. Для скрипта с русскими строками использовать `pwsh`, как при успешной подписи beta.4.
2. Проверить и безопасно обновить репозиторий:

   ```powershell
   git status --short --branch
   git fetch --prune origin
   git pull --ff-only
   ```

   Если есть локальные изменения или разошедшиеся коммиты, сначала сохранить и согласовать их. `reset --hard`, `git clean` и force push не применять.

3. Проверить локальные **JDK 21**, Android SDK и прежний `keystore.properties`. Файл ключа и пароли остаются на ПК. `local.properties` должен указывать на существующий SDK именно ПК: старый путь с другого компьютера нельзя использовать. Скрипт проверяет этот путь до сборки. Не переносить конфигурацию SDK с ноутбука.
4. Из чистого актуального `main` запустить:

   ```powershell
   pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\Build-SignedRelease.ps1 -ApplicationId com.joe6355.astrophoto
   ```

   Скрипт соберёт release, проверит package ID, versionCode ≥ 6, совпадение версии APK с метаданными, отсутствие отладки и действительную подпись. Сертификат должен совпасть с основной установкой: `79e37ad16c7cceaf6bae398d926e548e3f64ea0a6e248975cceb2a6e3d374f93`. При несовпадении кандидат не выдаётся как готовый.
5. В новой папке `artifacts/pc-signed-release-…/` получить **AstroPhoto-0.9.0-beta.5-signed-candidate.zip**. В нём ровно три файла:

   - `AstroPhoto-0.9.0-beta.5.apk` — подписанный основной APK;
   - `candidate.json` — коммит, версия, сертификат и SHA-256 APK/mapping;
   - `mapping.txt` — R8 mapping именно этой сборки.

6. Передать этот архив на ноутбук. Ключи, `keystore.properties`, `local.properties` и фотографии передавать не требуется. Если на ПК после подготовки beta.5 изменился код приложения, сообщить это вместе с архивом: исходники и проверки кандидата нужно сопоставить заново.

## Что находится в пакете ноутбука

Неподписанный release и его mapping служат проверяемым результатом локальной сборки. Их идентификаторы и SHA-256 будут зафиксированы после сборки в отчёте подготовки. **Неподписанный APK не предназначен для установки поверх основной версии.** Скрипт на ПК заново собирает и подписывает кандидат из чистого Git; для установки и диагностики использовать APK и mapping только из одного ПК-архива.

## После получения подписанного APK

На ноутбуке проверить архив, SHA-256, пакет, code6, отсутствие отладки, подпись и соответствие исходников. Перед обновлением сохранить свежий срез телефона. Обновлять только основную установку через `adb install -r`; существующие приложения не удалять, данные не очищать. После обновления достаточно короткой проверки запуска/сохранённых сессий и двух новых исправлений. Старые алгоритмические серии заново не прогонять.

Полный runtime beta.5 и обновление основной установки пока не пройдены. Подпись прежним ключом выполняется на ПК; сборка с другим ключом не подходит для сохранения существующей установки.
