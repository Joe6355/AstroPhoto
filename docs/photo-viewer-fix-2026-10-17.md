# Полноразмерный просмотр фотографий — 17.10.2026

Владелец дал приоритет качеству просмотра исходных кадров и обработанных файлов и потребовал сохранить существующие данные телефона. Для алгоритмов и просмотра выбраны пять готовых серий. Фотографии и диагностические материалы не публикуются в Git.

## Причина и исправление

Полноэкранный просмотр исходного JPEG вызывал `ContentResolver.loadThumbnail(...1800...)`: фактически показывалась системная миниатюра, увеличения не было. Результаты загружались с ограничением 3072 пикселя, сравнение — 1400; дальнейший zoom увеличивал уменьшенный bitmap. На проверенных исходниках 1440×1920 ограничение 3072 само по себе не уменьшало результат; для сравнения ограничение 1400 уже давало `inSampleSize=2`. Часть старых обработанных файлов имеет уменьшенный размер непосредственно в файле; просмотрщик не восстанавливает потерянные ранее детали.

Вместо этих трёх путей используется общий `PhotoViewer`:

- `PhotoRegionSource` читает JPEG/PNG через прежний `ProcessedImageSourceResolver` и `BitmapRegionDecoder`; при zoom/pan заново декодирует видимую область исходного файла. Полный огромный bitmap в память не загружается. Декодированная область ограничена 4 млн пикселей; начальный обзор временный и перекрывается детальным участком.
- При масштабе 1:1 и выше, в пределах бюджета области, читаются оригинальные пиксели (`inSampleSize=1`). Отрисовка идёт непосредственно в Canvas; при увеличении фильтрация пикселей выключена. При нехватке памяти возможна уменьшенная область с явным сообщением; `RGB_565` не используется.
- Кнопки «1:1» и «Вписать», pinch zoom, pan и двойной тап работают и для кадров серии, и для результатов. Границы перемещения учитывают размер изображения и пустые поля. Zoom привязан к положению пальцев. У маленьких изображений нет автоматического увеличения до размеров окна.
- Учтены все восемь EXIF-ориентаций, включая зеркальные. Сравнение использует общее состояние масштаба, положения и подсветки.
- «Подсветка» усиливает только отображение тёмных JPEG/PNG. Исходники, stacking, редактор, сохранение и экспорт от неё не меняются. При раскрытии управления подсветкой выбранный масштаб 1:1 сохраняется.
- Недоступный/повреждённый файл показывает ошибку вместо бесконечного индикатора. Декодер закрывается при смене файла/выходе, включая отмену загрузки; операции чтения выполняются вне UI-потока.

## Сохранность и установка

Устройство: Redmi 23021RAA2Y, Android 13/API 33, ADB `5cc69b3d`. На телефоне две ранее установленные версии: `com.joe6355.astrophoto` (release) и `com.example.astrophoto` (debug). Их APK и данные не заменялись. Оба сертификата отличаются от ключа ноутбука; ключ release находится на ПК. Для проверки использован отдельный `com.joe6355.astrophoto.qa20261017` и его test-пакет. Это не проверка совместимого обновления основной установки.

До тестов сохранены полный TAR `Pictures/AstroPhoto` (1458 файлов, 1 063 014 400 байт), TAR доступных внутренних данных прежнего пакета (222 файла, 86 052 352 байта) и обе существующие APK. Все 1458 файлов в резервной копии совпали с исходным инвентарём телефона по SHA-256. Внутреннее хранилище release недоступно ADB без ключа/прав отладки; установка поверх него не выполнялась. Проверочные изображения и скриншоты записываются только в приватный cache отдельной QA-версии.

## Проверка на телефоне

`PhotoViewerDeviceTest`: 3/3 успешно. Независимый PNG с однопиксельными линиями и точками сравнивается с декодированным участком попиксельно; дополнительно проверяется фактический снимок экрана 1:1, видимость тонких линий без размытия, изменение тёмных пикселей подсветкой и неизменность SHA-256 исходника. JPEG с EXIF 1…8 проверен по расположению цветных углов.

Опциональный `RealPhotoViewerDeviceAuditTest`: успешен на всех пяти сериях, 12 файлов — 5 исходных JPEG и 7 существующих результатов JPEG/PNG, включая Edited. Каждый открыт в 1:1 и с подсветкой; сохранены 24 снимка отображения. Этот тест не изменяет общие файлы и не запускается на чужих фотографиях без явных аргументов `realViewerAudit=true` и `viewerSessionPrefixes`.

Через обычный UI QA дополнительно проверены: открытие кадров сессии → JPEG → 1:1 → следующий кадр; результаты обработки → PNG → 1:1 → сравнение с первым Light. Отметки брака, обрезка, переименование и удаление при этом не вызывались.

Полный локальный gate `testDebugUnitTest`, debug/release lint, `assembleDebug`, `assembleDebugAndroidTest`, `assembleRelease --offline`: `BUILD SUCCESSFUL` за 10 мин 16 с. 103 unit-набора: 1136 тестов, 1133 успешно, 3 opt-in аудита личных файлов пропущены, 0 ошибок/падений. Debug и release lint: 0 ошибок, по 10 предупреждений (прежние 9 и рекомендация `Canvas.withTranslation` для нового блока отрисовки). Release APK без подписи и не устанавливался на телефон. Новый набор геометрии просмотра содержит 8 тестов, в том числе якорь pinch, границы изображения, native sample, ограничение памяти и отсутствие автоматического растягивания маленькой картинки.

Локальные материалы: игнорируемый `artifacts/viewer-2026-10-17/` — резервные копии, хеши, APK, скриншоты, журналы сборки и устройства. Полная обработка пяти выбранных серий относится к отдельному аудиту алгоритмов и не считается доказанной проверкой качества только по факту открытия фотографий.

## Ограничения

Исправление просмотра не делает нерезкий исходник резким и не восстанавливает отсутствующие в файле слабые детали. На исходном JPEG из серии `20260812_223507` с подсветкой различимы звёзды, берег и фон; усиление также делает заметны шум и полосы, уже находящиеся в файле. Часть остальных изображений очень тёмная непосредственно в JPEG/PNG — это отдельная задача обработки. Подписанный основной APK ещё нужно собрать прежним ключом и обновить через `adb install -r`, сохранив package ID и данные.
