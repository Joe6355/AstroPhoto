# Таймер, остановка серии и Dark Frames — 29.10.2026

Три оставшихся сценария камеры проверены на подключённом Xiaomi / Redmi 23021RAA2Y, Android 13. Использована уже установленная `com.joe6355.astrophoto.qa20261017`, beta.4 / code5, исходники `e8eea09`. Проверка начата 28.10 и завершена 29.10 в собственной `QA_CAMERA_GAPS_20261028`. Новых дефектов в этих сценариях не обнаружено; код и алгоритмы не менялись, APK не переустанавливались.

## Результаты

| Сценарий | Проверка | Результат |
|---|---|---|
| Отмена таймера | 10 кадров, пауза 2 с, таймер 10 с; подтверждён реальный запуск, затем системная кнопка «Назад» примерно через 3,69 с | Снимок экрана показывает начавшийся отсчёт. Журнал: `STOPPED`, 0/10. После окончания исходного времени отсчёта файлов нет, камера снова готова. |
| Остановка серии | Таймер 0, 10 кадров с паузой 2 с; кнопка «Остановить» примерно через 6,05 с после подтверждения | Сохранены 2 JPEG. Журнал: `STOPPED`, 2/10. Повторная проверка через 5 с не обнаружила новых кадров; после проверки Dark Frames число обычных JPEG также осталось 2. |
| Dark Frames | 3 кадра, JPEG, ISO 400, 1/30 с, AF | Ровно 3 файла `DarkFrames_*_001.jpg`–`003.jpg` в `Darks/JPEG`. На экране сообщение о завершении, кнопка снова доступна. Счётчики и сведения сессии: 2 обычных / 3 тёмных. |

Все пять новых JPEG независимо полностью декодированы на ноутбуке: **1440×1920, ISO 400, 1/30 с**. Их SHA-256 после копирования совпали с хешами на телефоне. Первые два файла находятся в `Lights/JPEG`, три следующих — в `Darks/JPEG` собственной тестовой сессии.

Закрытие объектива не подтверждалось. Проверена работа ветки сохранения Dark Frames и согласованность параметров, а не пригодность этих кадров для калибровки астрофотографий.

Первоначальная попытка 28.10 отменила только окно подтверждения запуска; она не засчитана как проверка отсчёта. После просмотра сохранённого снимка тест исправлен: теперь он отдельно подтверждает запуск. Итоговые результаты подтверждены экраном, файлами и журналом серии; исходные попытки сохранены отдельно.

- Все **1734 прежних общих файла** и **222 доступных внутренних файла legacy-установки** побайтно совпали с предварительным снимком. Добавлены только 5 собственных JPEG; итог — **1739 общих файлов**.
- Все **604 прежних внутренних файла QA** остались на месте. Изменился только служебный `files/profileInstalled`; прежние сведения сессий, отметки и настройки побайтно совпали после восстановления. Добавлены сведения собственной тестовой сессии; итог — **605 внутренних файлов QA**.
- Настройки камеры и прежний `series_capture_recovery.xml` восстановлены из резервной копии с проверкой исходных байтов. Прежнее отсутствие активной сессии QA восстановлено удалением только созданной тестом настройки; JPEG и сведения сессий оставлены.
- Все три APK, UID и `ceDataInode` прежние. Основная `com.joe6355.astrophoto` остаётся подписанной beta.3 / code4; второй исходный пакет — code3, QA — code5. Закрытые внутренние файлы основной установки недоступны для `run-as`; сравнение их хешей не заявляется.
- Удержание экрана при зарядке возвращено на исходный **0**.

## Статус выпуска

[CI исходников `e8eea09`](https://github.com/Joe6355/AstroPhoto/actions/runs/40732231623) завершился успешно; итог независимо проверен через GitHub API после перерыва. Локальный полный gate этих исходников ранее дал 1290 passed / 4 skipped, оба lint без ошибок. Для текущих проверок использована та же QA; повторный полный прогон для изменения отчёта не запускался.

Для основной установки следующим шагом остаётся beta.4, подписанная прежним ключом на ПК, и короткая проверка обновления / диапазона ISO с сохранением данных — [инструкция](iso-range-recovery-2026-10-28.md). Нового подписанного APK beta.4 на ноутбуке пока нет. Полная матрица физических ISO, выдержек, фокуса, ночного качества и остальные незакрытые пункты релизного чек-листа этим прогоном не закрыты.

Предварительные и конечные хеши, резервная копия, журналы, снимки экранов и пять собственных JPEG находятся только в игнорируемой `artifacts/camera-release-gaps-2026-10-28/`. В Git включён отчёт без личных файлов.
