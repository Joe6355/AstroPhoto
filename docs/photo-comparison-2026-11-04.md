# Полноэкранное сравнение фотографий — 04.11.2026

## Что изменено

По запросу владельца продолжена работа над самим приложением без ожидания подписи основной версии. Существующее сравнение в «Результатах обработки» доработано; второй просмотрщик и новые алгоритмы обработки не создавались.

- «Рядом» сохраняет прежние два синхронных изображения.
- «Фото 1» и «Фото 2» показывают выбранный снимок во всей области просмотра. Между ними сохраняются масштаб, выбранный участок и подсветка.
- Оба источника остаются открытыми, переключение не перезагружает файлы. Декодируются ограниченные видимые области прежним `PhotoViewer`/`PhotoRegionSource`; прежний предел4млн пикселей одной плитки сохранён.
- Скрытая фотография исключена из жестов и доступности: она не перехватывает касания видимой. Общие «Вписать», двойной тап, щипок и подсветка продолжают работать.
- Окно сравнения явно задаёт цвет фона и текста из темы. При визуальной проверке отдельного окна обнаружен чёрный текст на тёмном фоне; зависимость от цвета содержимого вызывающего экрана устранена.
- Подсказки сравнения сокращены, чтобы при200% и открытой подсветке сохранялась полезная область фотографии. Обычный одиночный просмотр сохраняет прежнюю подробную подпись подсветки.
- Файлы не записываются; обратное переключение в «Рядом» доступно из того же окна. Сравнение доступно и для двух результатов, и через прежнее сравнение результата с первым исходным light-кадром.

Файлы кода: [ProcessedResults.kt](../app/src/main/java/com/joe6355/astrophoto/ProcessedResults.kt), [PhotoViewer.kt](../app/src/main/java/com/joe6355/astrophoto/PhotoViewer.kt). ### Воспроизведение UI-приёмки при изменении этого кода

Нужен собственный эмулятор и отдельный `com.joe6355.astrophoto.qa20261017`; тестовые PNG создаются в его кеше и удаляются после проверки. В AndroidJUnitRunner передать `-e comparisonAudit true`, классы из `PhotoComparisonDeviceTest` запускать раздельно:

| Метод | Системный `font_scale` эмулятора |
|---|---|
| `fullFrameSwitchKeepsZoomPanAndDisplayLightAndUsesOnlyVisibleGestures` |1.0 |
| `fullFrameControlsRemainAccessibleAtTwoHundredPercent` |2.0 |

Тест требует фактическое значение из Android configuration. Подмена `LocalDensity` снаружи `Dialog` недостаточна; первая попытка такой проверки заменена запуском с системным200%. После проверки вернуть исходный шрифт эмулятора. Все ADB-команды адресовать его явному serial, не подключённому физическому телефону. Это инструкция воспроизведения после нового изменения/дефекта, а не требование повторить завершённый сценарий на другом компьютере.

Устанавливались только собственные QA/test APK на явно выбранный `emulator-5580`. Физический Xiaomi не обновлялся, его приложения/настройки/сессии/фотографии этим блоком не менялись. Последний подтверждённый срез телефона: QA ночного исправления `bc3aff8c…`, основной release/R8 `d8d875b5…` с ПК; в этом UI-блоке новые версии телефона не считывались. Перед последующей установкой сверить их фактически.

Тестовые изображения синтетические и проверяют UI/координаты, а не новое качество астрофотографии. Ночные пиксельные алгоритмы не менялись; [приёмку двух серий6d85d69](window-night-fix-2026-11-04.md) повторять не нужно. Синхронизация используется прежняя: одинаковое относительное положение и увеличение для изображений, а не дополнительное геометрическое совмещение разных снимков.

Следующий шаг применения — наПК получить текущий `main`, подписать изменённый основной APK прежним ключом по [PHONE_UPDATE_RU.md](PHONE_UPDATE_RU.md) и обновить поверх. Для текущего изменённого основного/R8-кандидата остаётся короткая проверка на телефоне; старую аппаратную матрицу и публикацию не открывать. Перепроходить это сравнение на эмуляторе без изменения кода/нового дефекта не требуется после окончательного результата.
