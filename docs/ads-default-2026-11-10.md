# Неперсонализированная реклама AstroPhoto — 10.11.2026

Владелец передал снимок ответа поддержки РСЯ. Поддержка подтвердила возможность показа неперсонализированной рекламы с первого запуска и рекомендовала убрать `AD_ID` при отсутствии персонализации. Письмо не содержит отдельного подтверждения для категории RuStore 0+ и не перечисляет поля сетевых запросов.

## Реализация

- Реклама включена по умолчанию без диалога. В «Настройки → Конфиденциальность» есть переключатель. Прежнее «Без рекламы» сохраняется при обновлении. Настройка хранится отдельно от параметров камеры и исключена из резервного копирования.
- Перед ручным запуском Yandex Mobile Ads 8.6.0 установлены `setAgeRestricted(true)`, `setUserConsent(false)`, `setLocationTracking(false)` и `setAppAdAnalyticsReporting(false)`. В объединённый манифест не включается разрешение `AD_ID`. Возрастное ограничение применяется ко всем пользователям. [Инициализация](https://ads.yandex.com/helpcenter/ru/dev/android/quick-start) · [Возрастное ограничение](https://ads.yandex.com/helpcenter/ru/dev/android/coppa) · [Удаление AD_ID](https://ads.yandex.com/helpcenter/ru/dev/android/ad-id) · [События AppMetrica](https://appmetrica.yandex.com/docs/ru/common/ads-sdk-integration).
- Нативное объявление запрашивается на главной после обучения. App Open сохраняет прежние условия холодного запуска и окно 700 мс. Отключение скрывает карточку и прекращает новые запросы со стороны приложения. Включение в настройках снова позволяет загрузить карточку при возвращении на главную.
- Политика и сведения для декларации обновлены. Сведения рекламного запроса и IP сетевого соединения указаны отдельно. Редакция политики для beta.6 доступна по ссылке из публичной политики. [Политика](PRIVACY_POLICY_RU.md) · [Декларация](DATA_DISCLOSURE_RU.md).

## Проверки

На отдельном Android 14 AVD `AstroPhotoAdsAPI34` с шрифтом 200% проверены офлайн-политика, сохранение прежнего отказа, загрузка нативной карточки без отдельного согласия, выключение и повторное включение, сохранение настройки после пересоздания и холодного запуска. В журнале холодного запуска с выключенной рекламой нет инициализации SDK или загрузки объявлений. Проверены также обязательные поля нативной карточки. Для проверки первого появления карточки обучение уже считалось пройденным. Использовались демонстрационные блоки Яндекса.

На beta.7 QA демо App Open показался, закрылся по кнопке «Вернуться в приложение» и не показался повторно при возврате. Для проверки загрузки у теста окно 40 секунд, в приложении остаётся 700 мс. Системное окно эмулятора помешало первому прогону. В следующем прогоне кнопка была видна в дереве веб-окна SDK, но старый поиск её пропустил. После исправления поиска тест прошёл за 16,94 с.

Девять целевых JVM-тестов логики App Open прошли. Проверочные debug, androidTest и release/R8 собраны, lint release без ошибок с 15 предупреждениями. `aapt` подтвердил отсутствие `AD_ID` в debug и release. Встроенная политика совпала с исходником. Первый сетевой прогон был прерван восстановлением сети эмулятора до запроса рекламы. После восстановления нативный сценарий прошёл. Локальные журналы и снимки в `artifacts/ads-default-2026-11-10/`.
