# Редактор: допустимая обрезка при узком предпросмотре — 29.10.2026

## Проблема и исправление

Редактор применял минимальный размер сохраняемого результата **200×200** к уменьшенному предпросмотру. Например, оригинал **4096×512** загружается для экрана как **1024×128**: прежний `renderPreview` возвращал `null`, и кнопка сохранения становилась недоступна даже без обрезки. Аналогичная ошибка мешала автоматической обрезке чёрных краёв.

Предпросмотр теперь рассчитывает обрезку с минимумом один отображаемый пиксель; округление и ограничения процентов сохранены. Отдельно проверяется размер оригинала: сохраняемый PNG по-прежнему должен иметь обе стороны не меньше 200 пикселей. Для действительно маленького исходника экран показывает причину недоступного сохранения. Автообрезка анализирует прежний предпросмотр, но проверяет допустимость найденных процентов по размерам оригинала.

Потоковое сохранение полного разрешения из [предыдущего исправления](editor-full-resolution-save-2026-10-29.md), преобразование цвета и резкости, алгоритмы сложения и прежние эталоны обработки не менялись.

## Проверки

- **33 связанных JVM-теста прошли:** 8 новых проверок узкого предпросмотра, прежние 8 проверок потокового выхода и 17 проверок ручных параметров/пресетов. Проверены горизонтальный и вертикальный исходники, округление на границе минимального размера, предпросмотр в 1–4 пикселя и сохранение запрета действительно маленького выхода.
- QA app/test APK собраны; оба lint QA — **0 ошибок**, по 11 предупреждений.
- На прежней QA Android-тест воспроизвёл точный отказ: `Valid native 4096x512 must not be blocked by preview 1024x128`. Совместимый тестовый APK собран до изменения production-кода; сама QA при этом оставалась прежней.
- После обновления только QA тот же тест прошёл все **четыре случая** горизонтального и вертикального предпросмотра с обрезкой и без неё. Отдельный тест сохранил **четыре полноразмерных PNG**; все пиксели совпали с полноразмерным расчётом. Недопустимая нативная обрезка отклонена без новых выходов и изменения сведений сессии; слишком сильная автообрезка также отклонена.
- Через обычный интерфейс открыт собственный PNG **204×3604** с предпросмотром **51×901**. Кнопка «Автообрезка» применила обрезку до **204×3540**, затем «Сохранить копию» создала отдельный PNG именно этого размера. Экран успеха и снимок сохранены. Все **пять новых PNG** полностью декодированы на ноутбуке; четыре инструментальных результата независимо сверены по хешам всех ARGB-пикселей.
- Основной оптимизированный release без подписи и основной Android test APK собраны; оба lint основной конфигурации — **0 ошибок**, по 10 предупреждений. Release имеет пакет `com.joe6355.astrophoto`, beta.4 / code5, SHA-256 `f90dd71c6021d917d83f609239831a51777c2d0c76012cad4e2d172c7a247be7`. На телефон он не устанавливался.
- Полный JVM-набор локально повторно не запускался. Коммит исправления `4dda531` [прошёл полный CI](https://github.com/Joe6355/AstroPhoto/actions/runs/40912980930): unit tests, оба lint, Android test APK, debug/release build. Для проверки на телефоне дополнительных изменений production-кода не потребовалось.

## Данные и установка

Перед проверкой сохранены хеши **1750 общих файлов**, **222 доступных внутренних файлов legacy** и **608 внутренних файлов QA**, а также резервная копия внутренних данных QA. Финальное сравнение подтвердило:

- Все 1750 прежних общих и 222 legacy-private файла побайтно прежние. Добавлены только пять PNG собственной новой сессии; итог — **1755 общих файлов**.
- В QA все прежние сведения сессий, отметки и настройки побайтно прежние; изменился только служебный `files/profileInstalled`. Добавлены сведения собственной сессии и её пустые отметки; итог — **610 внутренних файлов QA**. Удалений нет.
- Обе исходные APK прежние; UID и `ceDataInode` всех трёх установок сохранены. Закрытая область основной установки недоступна для `run-as`; сравнение хешей её внутренних файлов не заявляется.
- Только QA обновлена через `install -r` прежним ключом; SHA-256 установленного APK `c38060120ddef861dba503a6e173119bed67cc6613d5a2ae0e9062ed87494e92`. Удаления приложений или очистки данных не было. Удержание экрана возвращено на исходный **0**.

Основная установка остаётся подписанной **beta.3 / code4**. Новый код относится к **beta.4 / code5**; подписание накопленных изменений прежним ключом на ПК отложено владельцем. Это не мешает сборке и проверкам отдельной QA.

APK, полные логи, XML проверок, снимок исходного состояния и резервная копия находятся только в игнорируемой `artifacts/editor-preview-crop-2026-10-29/`.
