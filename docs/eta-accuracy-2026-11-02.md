# ETA при меняющейся скорости — 02.11.2026

Второй блок запроса владельца после [ресурсных сообщений](resource-clarity-2026-11-02.md). Доработки выполнены на ноутбуке; другой телефон ещё не подключён и не проверен.

## Расчёт

[ProcessingEtaEstimator.kt](../app/src/main/java/com/joe6355/astrophoto/ProcessingEtaEstimator.kt) раньше делил всё прошедшее время этапа на выполненную работу. Медленный первый шаг или изменение скорости продолжали влиять на весь оставшийся прогноз.

Теперь используется недавнее окно около 4 секунд, с сохранением минимум двух интервалов для медленных шагов. Частые тайловые callbacks объединяются с шагом не чаще 250 мс, поэтому несколько последних миллисекунд не вытесняют полезную выборку. При равномерной работе сохраняется измеренный темп; после разогрева, ускорения и замедления старые интервалы уходят из расчёта.

Смена этапа/общего числа единиц, откат прогресса и часов требуют новых измерений. Повторный callback без роста счётчика не искажает измеренную скорость; при просроченной оценке возвращается неизвестное время вместо 0 сек. Положительная доля миллисекунды также не превращается в отображаемый 0. Счётчик прогресса и состояние завершения не подменяются.

ETA остаётся **оценкой текущего этапа**. Она пересчитывается по настоящим callbacks; отдельный таймер прогресса не добавлялся. При полном отсутствии callbacks значение не пересчитывается до следующего сообщения. Точность всех будущих этапов и всей длительности обработки не обещается.

## Проверка на настоящем конвейере

Новый opt-in [ProcessingEtaPipelineDeviceTest](../app/src/androidTest/java/com/joe6355/astrophoto/ProcessingEtaPipelineDeviceTest.kt) создал четыре собственных JPEG 128×256 и выполнил настоящий Average. В progress callbacks тайловой интеграции намеренно добавлялись задержки: для первых 37,5% строк по 200 мс на callback, затем по 1800 мс. Физическая память/диск не исчерпывались, пиксели и алгоритм не менялись.

Получены 8 наблюдений. Фактический остаток до последнего callback этого этапа сравнивался с прежней формулой и новым оценщиком на одних временных отметках:

| Прогресс | Фактически осталось, с | Прежний ETA, с | Новый ETA, с |
|---|---:|---:|---:|
|192/256|3,615|2,337|3,619|
|224/256|1,807|1,275|1,808|

Средняя абсолютная ошибка двух поздних прогнозов: прежняя 904,5 мс, новая 2,5 мс. **Это контролируемое замедление, не универсальный процент точности на ночных сериях.** Исходники совпали по SHA, PNG полностью декодирован как 128×256, удалён только собственный URI результата. JUnit 10,163 с.

Повтор прежнего [ProcessingEtaDisplayDeviceTest](../app/src/androidTest/java/com/joe6355/astrophoto/ProcessingEtaDisplayDeviceTest.kt) обоснован изменением оценщика: **прошёл за 5,289 с**. Настоящие UI и уведомление совпали («До конца этапа ≈ 6 сек», 2/10), новый этап сбросил ETA, настоящий PendingIntent остановил задачу и удалил уведомление. Снимок просмотрен. Этот второй сценарий синтетический и отдельно не доказывает точность JPEG-конвейера.

QA assembleDebug/assembleDebugAndroidTest, целевые unit и lintDebug — **BUILD SUCCESSFUL за 2 мин 50 с**, lint 0 ошибок/fatal, 14 предупреждений. Полный локальный набор всех JVM здесь не запускался.
