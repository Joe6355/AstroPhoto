## Подтверждённые дефекты

### P1 — Deep Sky не прошёл regression gate

Повторный полный JVM-прогон: 1105 тестов, 19 падений. Из них 14 останавливаются на одном gate: `Active file-backed Stage 4 differs from component replay by more than 2 levels: maximum=5, differentPixels=280649`. Ещё четыре теста Stage 4/композиции не совпадают с ожиданиями, включая расхождение одного ARGB-значения на 1. Это не доказывает визуальный дефект, но до выяснения причины нельзя считать новую RGB16/Deep Sky обработку регрессионно безопасной.

Оставшееся падение — структурная проверка исходного кода, ожидающая четыре дублированных вызова manual alignment вместо единого координатора. Её нужно заменить поведенческим тестом, а не возвращать дублирование.

### P1 — `session_info.txt` не создаётся на Android 13

При создании QA-сессии интерфейс показал:

`Primary directory Pictures not allowed for content://media/external/file; allowed directories are [Download, Documents]`.

Причина подтверждается кодом `ShootingSessionStore.writeInfoWithMediaStore`: текстовый файл вставляется через `MediaStore.Files` в `Pictures/AstroPhoto/...`. Сами JPEG сохранились, но метаданные сессии не записываются, поэтому часть сведений после импорта/переустановки может отсутствовать. Пользователю показывается длинное системное сообщение.

### P2 — интерфейс списка сессий ломается при крупном шрифте

При `font_scale=1.3` длинное имя активной сессии забирает ширину строки, а метка `Активная` переносится по одной букве и растягивает карточку примерно на 680 px по высоте. Причина — имя и метка находятся в `Row` с `Arrangement.SpaceBetween`, но имя не ограничено весом/строками. Исходный системный масштаб 0.81 восстановлен.

### P2 — выбранная выдержка и EXIF отличаются

UI показывал 1/60 с, а три JPEG содержат EXIF `ExposureTime=0.02 s` (1/50 с). Нужно сверять также `CaptureResult.SENSOR_EXPOSURE_TIME`: EXIF может быть округлён/переписан OEM, поэтому источник расхождения пока не установлен.

### P3 — неоднозначность экранов обработки

После успешного Average приложение сразу открывает редактор, где доступны пресеты `Звёзды — заметно/максимум`, хотя тестовая сцена была городской и почти без звёзд. Это не сбой, но названия вводят пользователя в заблуждение. На экране сессии одновременно есть `Пресеты`, `Ручная обработка`, `Автоматическая обработка`, `Подробнее/Открыть`, а после результата — ещё отдельный редактор с `Пресеты/Ручная`.

## Что не удалось завершить

- Compose UI-тесты (`HomeScreenTest`, `AboutScreenTest` и остальные на `createComposeRule`) зависают до assertions: test Activity не выходит на экран, в фокусе остаётся MIUI Launcher. Запуски остановлены вручную после отсутствия прогресса; считать их пройденными нельзя. Не-Compose device-тест и собственный real-photo instrumentation работают.
- Deep Sky на серии `дорога_20` остановился с 1/10 кадров при минимуме 4. Сам по себе успешный прогон `пересииды_30` не доказывает, что отказ другой серии корректен. Позднейшая диагностика по сохранённой копии воспроизвела отказ уже на первичном выравнивании; подробности в `device-audit-fixes-2026-09-08.md`.
- Искусственный тест нехватки места не выполнялся: при 102 ГБ свободного места безопасно воспроизвести его без изменения состояния устройства нельзя.
- Поворот во время тяжёлой обработки отдельно не прогонялся. Тест выключения экрана вызывал стекер напрямую из instrumentation: он не покрывает жизненный цикл обработки через UI и foreground service.
- На телефоне остались отдельные QA-сессии/копии. Они не входят в резервную копию исходных 49 сессий и явно названы `QA`; автоматически не удалялись.

## Рекомендуемый порядок исправлений

1. Найти источник расхождения Stage 4 RGB16 с replay и восстановить regression gate; не обновлять baseline вслепую.
2. Перенести хранение `session_info` на допустимый механизм и показывать короткую пользовательскую ошибку.
3. Исправить адаптивную раскладку карточки сессии при длинном имени/крупном шрифте.
4. Логировать requested и фактический `SENSOR_EXPOSURE_TIME` и явно показывать фактическое значение после кадра.
5. Исправить harness Compose UI-тестов, чтобы test Activity гарантированно запускалась на MIUI, затем повторить UI-набор.

Артефакты: скриншоты, UI XML, три тестовых JPEG, резервная копия и результаты Gradle находятся в `artifacts/device-qa-20260905` и `app/build/reports`.
