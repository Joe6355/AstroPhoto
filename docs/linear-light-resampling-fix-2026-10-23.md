# Сохранение света при совмещении JPEG — 23.10.2026

При сдвиге на долю пикселя автоматическое сложение смешивало соседние значения sRGB и лишь затем переводило смесь в линейный свет. Из-за нелинейности sRGB это занижало свет компактных источников. Теперь каждый соседний пиксель переводится в линейный свет **до** билинейной интерполяции. Для `LinearRgbPixelSource` используются исходные RGB16 без промежуточного ARGB8.

Исправлены оба пути `LinearWeightedIntegrator`: с фильтром дефектов сенсора и без него, для RGB16 и совместимого ARGB8-вывода. Таблица преобразования 256 кодов sRGB общая для экземпляров семплера; новые объекты в цикле по пикселям не создаются. Формулы отображения координат, покрытие, проверка четырёх соседей маской, веса и пороги регистрации сохранены. Выборка sRGB для геометрических патчей остаётся прежней. Историческая `SamplingFidelityDiagnostic` также измеряет encoded-sRGB патчи; её отношение контрастов не является измерением фотометрического выигрыша новой интеграции.

Версия интеграционного checkpoint повышена с 9 до 10. Сложение и зависимая постобработка старого алгоритма не восстанавливаются как новые. Сохранённые фотографии и пользовательские сессии не мигрируют и не перезаписываются.

## Воспроизведение ошибки

Контрольный полупиксельный отсчёт между чёрным и белым должен содержать 0,5 линейного света. Старый порядок операций давал около 0,214. Это искусственный контрастный пример, а не процент потерь на всех фотографиях.

До исправления 5 из 6 новых интеграционных регрессий упали: свет в отдельных каналах, сумма света одиночной звезды, RGB16 identity, RGB16 fractional и robust/ARGB8. Проверка всех 256 целочисленных кодов прошла уже на старой версии. После изменения эти проверки и связанные тесты сенсорной маски/checkpoint прошли: 72 теста без отказов. Добавлены отдельные проверки границ/нечисловых координат и неизменности геометрической sRGB-выборки.
