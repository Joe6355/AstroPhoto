## 2. Проверить системную совместимость

Подтверждённый физический аппарат — Xiaomi23021RAA2Y, Android13. До подачи проверить системную часть на **API34 и API35+**: запуск, отказ/выдача разрешений, частичный доступ к фото, открытие сессии, foreground-обработка, отмена и возврат из фона. Для этого подходит эмулятор; аппаратную Camera2-съёмку он не подтверждает.

Особый приоритет — служба обработки: `mediaProcessing` появился с [Android15](https://developer.android.com/about/versions/15/changes/foreground-service-types), а manifest AstroPhoto использует его и при установке на более ранние ОС. Отказ на API34 пока не воспроизведён. Проверять конкретный сценарий, не менять архитектуру по предположению.

Новая ночная серия и другая физическая камера остаются отдельной проверкой качества/совместимости. До их появления описание не должно обещать идеальные звёзды, одинаковые выдержки и работу всех режимов на любом телефоне.

Минимальная версия Android берётся из manifest. Нужны минимум три скриншота телефона: PNG/JPG, каждый до3МБ и не выше2160×3840; иконка512×512 до3МБ с заполненным фоном. ## 5. Заполнить безопасность данных и разрешения

[Руководство RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/new-version-app/declare-app-permissions/how-to-declare-permissions) требует указать типы данных, к которым приложение обращается, и объяснить выявленные чувствительные разрешения. Фактический список формируется при обработке APK. Категории не определяются одним наличием или отсутствием сетевого разрешения.

Подготовить обоснования по текущему manifest, затем сверить с финальным APK:

| Разрешение/доступ | Основание в AstroPhoto |
|---|---|
| CAMERA | Preview и создание JPEG-снимков/серий |
| READ_MEDIA_IMAGES / READ_MEDIA_VISUAL_USER_SELECTED | Просмотр и обработка доступных пользователю изображений; отдельно проверить ограниченный выбор фото |
| READ_EXTERNAL_STORAGE доAPI32 | Доступ к сессиям на прежних Android |
| WRITE_EXTERNAL_STORAGE доAPI28 | Сохранение снимков/экспортов на прежних Android |
| FOREGROUND_SERVICE / CAMERA / MEDIA_PROCESSING | Видимая пользователю серия и длительная обработка с уведомлением/остановкой |
| POST_NOTIFICATIONS | Прогресс и управление текущей задачей |
| VIBRATE | Включаемый пользователем сигнал завершения |

Здесь не назначены ответы вместо фактической анкеты консоли. Нужно отдельно обозначить локальную обработку, выбранную пользователем отправку, системный backup и отсутствие собственного сервера. Необязательное разрешение не должно становиться условием несвязанной функции.

## 6. Зафиксировать и подписать один окончательный кандидат

Сначала закончить обязательные кодовые изменения, CI и относящиеся к ним проверки. Затем выбрать версию; следующий изменённый кандидат планировать с `versionCode > 6`, чтобы не выдавать два разных APK за один обновляемый выпуск. Название `beta` и окончание тестового этапа определяет владелец по фактической готовности.

Основной ID — **`com.joe6355.astrophoto`**. Прежний сертификат SHA-256 — **`79e37ad16c7cceaf6bae398d926e548e3f64ea0a6e248975cceb2a6e3d374f93`**. Ключ остаётся на ПК. [RuStore принимает APK и AAB](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/apk-signature); для APK используется цифровая подпись. Сохранение прежнего сертификата обеспечивает совместимое обновление нынешних установок Android.

Из чистого актуального `main` на ПК, PowerShell7/JDK21/свой Android SDK:

```powershell
git status --short --branch
git fetch --prune origin
git pull --ff-only
pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\Build-SignedRelease.ps1 -ApplicationId com.joe6355.astrophoto
```

При локальных изменениях сначала сохранить и согласовать их; не применять принудительную очистку/перезапись истории. Получить один архив **APK + candidate.json + mapping.txt**; зафиксировать source SHA, версию, хеш APK и сертификат. Скрипт уже проверяет подпись, non-debuggable и метаданные, но его текущий нижний порог versionCode≥6 сам по себе не доказывает повышение относительно установленной beta.5 — это проверить отдельно.

На телефоне сохранить свежий исходный срез и обновить совместимый основной пакет без удаления/очистки. Проверить **новые** политику/UI, затронутый системный сценарий и сохранность данных/настроек. Старые сигналы, Σ30, dark frames, полную приёмку beta.4 и все контрольные серии без изменения соответствующего кода повторять не нужно.

`mapping.txt` сохраняется для диагностики именно этого APK; ключи/пароли/фотографии/локальные архивы в Git не добавляются. Прежний [beta.5 UI-кандидат](beta5-long-text-preparation-2026-11-01.md) остаётся доказательством своей сборки, но не заменяет будущие изменения политики и версии.

## 7. Загрузка, проверка магазина и публикация

1. После готовности комплекта открыть карточку и загрузить **окончательный подписанный APK**, сопоставив его SHA с `candidate.json`. QA-пакет и unsigned-эталон не являются кандидатами для основной карточки.
2. Заполнить карточку, безопасность данных и пояснение модератору. Проверить совместимость и предупреждения консоли. Сохранить версию как черновик, а сведения о загруженном файле записать в датированный отчёт.
3. Выбрать путь первой выдачи. В RuStore доступны [закрытая альфа](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/testing/alpha-testing) и [открытая бета](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/testing/beta-testing). Тестовая версия тоже проходит модерацию. Для альфы официальный процесс отдельно описывает переход на основную версию; ценные рабочие данные не подвергать удалению ради смены канала.
4. После проверки карточки получить отдельное разрешение владельца на отправку. Зафиксировать ответ RuStore. Если модерация успешна, согласовать ручную публикацию.
5. Проверить получение из RuStore и совместимое обновление на собственном устройстве/тестовой копии, собрать внешние дефекты с моделью/Android/версией/шагами. Записать карточку, versionCode, исходный SHA, хеш и ссылку на отчёт в `CONTINUE_HERE_RU.md`.

Автоматическая публикация, регистрация кабинета и отправка на модерацию этим аудитом не выполнялись. Готовность магазина подтверждается реальными результатами консоли, не наличием GitHub Release.
