# Понятная ошибка нехватки места при сложении

31.10.2026. При имитированном сбое записи ручное JPEG-сложение возвращало `write failed: ENOSPC`, профиль — тот же текст с названием этапа. Теперь оба пути сообщают: **«Недостаточно свободного места для обработки. Освободите место и повторите обработку.»** Профиль сохраняет название этапа, исходная причина остаётся в цепочке исключений.

Использован существующий `storageWriteFailure`, уже применяемый к JPEG/ZIP/MP4. Добавлен текст для обработки; граница `runManualStackingOperation` и завершение `JpegStacker.profileStack` используют этот преобразователь. Отмена продолжает выбрасываться как `CancellationException`; остальные ошибки не переименовываются в нехватку места. Уже переведённая ошибка не оборачивается повторно. Отбор, геометрия, веса, пиксели, пороги и алгоритмические эталоны не изменены.

## Проверки

Xiaomi 23021RAA2Y / Android 13, отдельная QA. `StackStorageFailureDeviceTest` включается только с `stackStorageAudit=true` и новым `stackStorageTag`. Для каждого сценария создаются четыре собственных JPEG **64×64**. Отдельный `ContextWrapper` направляет `files`, `cache` и `applicationContext` в новый каталог теста внутри QA cache; старые checkpoint и пользовательские сведения не используются.

Ошибка `IOException(ENOSPC)` намеренно выбрасывается **из progress callback**: в обычном сложении после реального тайла, в профиле после начала анализа. Память телефона не заполнялась, настоящий отказ файловой системы не воспроизводился.

| Сценарий | До исправления | После исправления |
|---|---|---|
| Average, четыре JPEG | Сырой ENOSPC, регрессия сообщения падает | Понятное сообщение, причина сохранена; повтор создаёт читаемый PNG64×64 из четырёх кадров |
| «Улучшение фото» | Этап + сырой ENOSPC, регрессия падает | Этап + понятное сообщение, причина сохранена, PNG не публикуется |

В обоих отказах проверены SHA-256 исходных тестовых JPEG, точные байты исходных сведений, отсутствие опубликованного PNG и удаление временного каталога обработки. После успешного повтора Average источник прежний, PNG полностью декодирован Android `BitmapFactory`; удалён только его собственный URI, строк результата данного теста не осталось.

На прежней QA две проверки упали **только на ожидаемом сообщении**, **0,838 с**; проверки сохранности и очистки до этих утверждений прошли. На исправленной QA **2/2 прошли за 1,221 с**. Повтор профиля до готового результата на искусственных одноцветных JPEG не выполнялся.

`assembleDebug`, `assembleDebugAndroidTest`, адресный `testDebugUnitTest`, `lintDebug` — `BUILD SUCCESSFUL`, **5 мин 52 с**. Прошли **27 JVM-тестов**, без ошибок и пропусков: `StackStorageFailureTest` (5), `ManualAlignmentPathSelectionTest` (12), `JpegProfileOutcomeTest` (10). Проверены вложенный ENOSPC, сохранение причины, другая I/O-ошибка, отмена с текстом ENOSPC и уже понятное исключение. Lint: **0 ошибок, 11 предупреждений**.
