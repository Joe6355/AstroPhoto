# Сохранение JPEG при ошибках записи — локальная проверка 30.10.2026

Работа выполнена **без телефона**: без ADB, установок, чтения или изменения данных устройства.

## Исправления

- Камера проверяет подтверждение публикации JPEG в MediaStore. Нулевое количество обновлённых строк больше не считается сохранённым кадром. Пустой JPEG также отклоняется; при отказе удаляется только новая запись этого снимка.
- При `ENOSPC` или `No space left on device` в цепочке причин показано сообщение: «Недостаточно свободного места для снимка. Освободите место и повторите съёмку». Первоначальная причина сохраняется; ошибка очистки не скрывает ошибку записи, отмена остаётся отменой.
- Для Android 8–9 JPEG сначала записывается во временный файл в папке назначения, затем выполняются flush/sync/close и проверка длины. Перенос в конечное имя выполняется без `REPLACE_EXISTING`. При совпадении имени, включая файл, появившийся во время записи, новый снимок получает числовой суффикс. Прежний файл сохраняется, а ошибка записи или закрытия очищает собственный временный файл.
- Камера возвращает фактическое имя legacy-файла. Ошибка запроса сканирования галереи после успешного сохранения регистрируется в журнале и не превращает готовый снимок в ложную ошибку съёмки.

Классификация нехватки места и очистка нового выхода общие с [ZIP](zip-storage-fix-2026-10-30.md); поведение ZIP сохранено. Обработка изображения, параметры камеры и прежние эталоны не менялись.

## Проверки

Сначала прежняя логика сохранения выделена в функции без изменения поведения. Из **15 локальных проверок** 11 воспроизвели отсутствующие гарантии: неподтверждённую публикацию, пустой снимок, сообщения о нехватке места, скрытую ошибку записи, перезапись совпавшего имени и оставшиеся частичные файлы. Это сценарии проверки, а не 11 отдельных дефектов. Исходная версия функций и XML прогона сохранены.

После исправления прошли **27 JVM-тестов**, без ошибок и пропусков: 8 публикации JPEG, 7 файлового сохранения JPEG и 12 регрессионных проверок ZIP. Тесты используют локальные потоки, колбэки публикации и отдельные временные каталоги. Они проверяют точные байты и операции записи, а не аппаратную съёмку или декодирование JPEG. Реальное хранилище не заполнялось.

Основные debug, Android test APK и оптимизированный release собраны, общий gate завершился успешно за **4 мин 37 с**. Оба lint — **0 ошибок / по 10 предупреждений**. Полный JVM-набор локально повторно не запускался; его выполняет CI после публикации.

Release **без подписи**: пакет `com.joe6355.astrophoto`, beta.4 / code5, SHA-256 `c06a131762e40b559f4b640c5fe34c9ddc5892c2052e2af162b1fb01310da039`. Сохранены APK и соответствующий mapping.
