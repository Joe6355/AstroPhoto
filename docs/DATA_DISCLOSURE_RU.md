## Данные и назначения

| Категория | Как используется | Передача с устройства |
|---|---|---|
| Фотографии, результаты JPEG/PNG/MP4 | Съёмка, локальная обработка, просмотр, редактор и таймлапс | Собственной отправки разработчику/SDK нет. «Поделиться» отправляет выбранный файл выбранному пользователем приложению |
| EXIF, параметры камеры, сведения/заметки сессий, отметки кадров | Организация сессий, выбор кадров, обработка и экспорт | Локально; сведения могут находиться в экспортируемом ZIP/изображениях. В рекламный запрос не добавляются |
| Настройки, журнал/промежуточные этапы обработки и кеш | Восстановление настроек, диагностика и продолжение обработки | Собственной сетевой отправки нет. Android может резервировать часть данных приложения согласно системным настройкам |
| Сведения рекламного запроса и IP сетевого соединения | Загрузка, показ и учёт неперсонализированных объявлений Yandex Mobile Ads | При включённой рекламе, в том числе по умолчанию. Перед ручной инициализацией установлен возрастной режим, выключены геолокация и отчётность о рекламных событиях в AppMetrica. Разрешение `AD_ID` удалено |
| Настройка показа рекламы | Управление запуском SDK и запросами объявлений | Локальные preferences, исключены из cloud backup/device transfer. Не передаются как файл на сервер разработчика |
| E-mail, текст и вложения обращения | Ответ пользователю и решение его вопроса | Только если пользователь самостоятельно отправляет письмо; отправка выполняется почтовым приложением/сервисом, не автоматически AstroPhoto |

Показ включён по умолчанию. Если пользователь ранее выбрал «Без рекламы» или выключил переключатель, приложение не инициализирует рекламный SDK при новом запуске. Отключение скрывает карточку и прекращает новые запросы объявлений со стороны приложения. Уже отправленные запросы могут завершиться. Съёмка и обработка доступны при любой настройке.

Компоненты AppMetrica остаются в составе Yandex SDK. AstroPhoto отключает отправку автоматических рекламных событий вызовом `setAppAdAnalyticsReporting(false)`. Итоговые категории нужно сверить с формой RuStore и манифестом подписанного APK. [Категории данных Yandex SDK 8](https://ads.yandex.com/helpcenter/ru/dev/android/app-privacy-android) · [Интеграция с AppMetrica](https://appmetrica.yandex.com/docs/ru/common/ads-sdk-integration).

## Разрешения окончательного APK

| Разрешение/группа | Объяснение для декларации |
|---|---|
| CAMERA | JPEG-съёмка, preview и серии по действию пользователя |
| READ_MEDIA_IMAGES / READ_MEDIA_VISUAL_USER_SELECTED | Доступные изображения и сессии на поддерживаемых версиях Android; учесть выбранный/ограниченный доступ |
| READ_EXTERNAL_STORAGE доAPI32 / WRITE_EXTERNAL_STORAGE доAPI28 | Совместимость работы с файлами на старых Android |
| POST_NOTIFICATIONS | Статус съёмки/обработки и действия в уведомлении |
| FOREGROUND_SERVICE и CAMERA/DATA_SYNC/MEDIA_PROCESSING | Продолжение текущей серии и обработки, отображение их состояния |
| VIBRATE | Сигнал завершения по настройке пользователя |
| INTERNET / ACCESS_NETWORK_STATE | Работа рекламного SDK при включённой рекламе |
| com.google.android.gms.permission.AD_ID | Исключено из объединённого манифеста |
| com.google.android.finsky.permission.BIND_GET_INSTALL_REFERRER_SERVICE | Транзитивное разрешение SDK для получения install referrer. Включить в сверку итогового манифеста |

Разрешений ACCESS_FINE_LOCATION/ACCESS_COARSE_LOCATION, микрофона, контактов, SMS и телефона в manifest приложения нет. Из отсутствия геолокационного разрешения не следует, что сетевой сервер не получает IP. Нельзя объявлять новую сборку полностью офлайн или не передающей никаких данных.

## Хранение и управление

Оригиналы, сессии и экспорты — до удаления пользователем; служебные данные/кеш — до очистки соответствующим механизмом приложения или Android. Системные/галерейные копии и выбранные внешние приложения управляются отдельно. Рекламные серверные данные и срок их хранения регулируются [политикой Яндекса](https://yandex.ru/legal/confidential/).
