## На ПК — только для следующего нового кандидата

1. Открыть PowerShell7 в папке проекта. Проверить чистое дерево, сохранить свои изменения при наличии, получить текущий main:

   ```powershell
   git status --short --branch
   git fetch --prune origin
   git pull --ff-only
   ```

   Если ветки разошлись — согласовать изменения, без reset/clean/force push. Сверить актуальную точку продолжения и действительно новые производственные изменения после принятого `a7e754e`; одни изменения документов не требуют новой сборки.

2. Использовать прежний локальный `keystore.properties`, его ключ, JDK21 и SDK именно ПК. На ноутбуке ключа нет; переносить его и пароли не требуется.

3. Из чистого актуального main выполнить существующий скрипт:

   ```powershell
   pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\Build-SignedRelease.ps1 -ApplicationId com.joe6355.astrophoto
   ```

   Скрипт заново соберёт и подпишет текущий код. Основной ID `com.joe6355.astrophoto`; сертификат SHA-256 **`79e37ad16c7cceaf6bae398d926e548e3f64ea0a6e248975cceb2a6e3d374f93`**. На момент фикса версия beta.5/code6; дальнейшие изменения должны совпадать с метаданными выбранного кандидата.

4. Получить созданный **signed-candidate.zip** с APK, `candidate.json`, `mapping.txt` и перенести этот один архив на ноутбук. Имя папки `artifacts/pc-signed-release-…/` скрипт выведет сам. Через git pull архив не передаётся. Ключи, локальные properties и фотографии в архив не входят.

## На ноутбуке после получения

Проверить архив, package/версию, хеш APK, прежний сертификат и исходный SHA. Старый unsigned1810fbf и APK с другой подписью не заменяют новый signed-кандидат. APK и mapping брать только из одного архива.

Перед установкой сохранить **свежий фактический** срез телефона; не применять старые настройки как обязательные. Обновлять основной пакет поверх через `adb install -r`, без удаления приложения и очистки данных.

После следующей согласованной установки проверить только вошедшие с прошлого кандидата изменения, одну короткую собственную серию с EXIF ISO/выдержки и сохранность прежних файлов/настроек. Учесть готовые ресурсные сообщения/ETA и новую подготовку служебной камеры; всю старую приёмку повторять не нужно. Полный private основной non-debuggable установки может быть недоступен для сплошного хеширования; границы записать честно.

Новый круг контрольных серий, сигналов,Σ30,dark, полной цепочки редактор/ZIP/MP4 ради этого обновления не нужен. Зафиксировать фактический результат в `CONTINUE_HERE_RU.md`; после этого сокращённый текущий этап можно закрыть.
