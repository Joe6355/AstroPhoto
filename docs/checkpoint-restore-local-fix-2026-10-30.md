# Сохранённый прогресс при ошибке восстановления — 30.10.2026

Пункт выполнен локально, **без телефона, ADB и установок**.

## Изменение

При ошибке копирования готового checkpoint в рабочую папку код удалял исходную контрольную точку вместе с сохранённой постобработкой. Затем возвращал `null`, который вызывающий этап считал отсутствием кэша и переходил к повторному вычислению.

Теперь I/O-ошибка после начала восстановления очищает частичные рабочие копии, сохраняет исходные файлы checkpoint и передаётся вызывающему коду с понятным сообщением: «Не удалось восстановить обработку. Прогресс сохранён. Проверьте свободное место и доступность хранилища, затем повторите». Исходная причина остаётся в `cause`.

Это останавливает текущий запуск вместо пересчёта: оба вызывающих этапа читают checkpoint до вычисления, а `JpegStacker` удаляет сохранённые контрольные точки только после успешной обработки. После устранения проблемы можно повторить восстановление из прежних данных. Незавершённый временный файл постобработки также очищается.

Ошибки целостности и несовместимые данные по-прежнему удаляют недостоверный checkpoint и позволяют пересчёт. Формат, версия и ключи checkpoint, алгоритмы регистрации/сложения и эталоны изображений не менялись.

## Проверка

Две новые проверки сначала воспроизвели удаление пригодного кэша на прежнем коде: при сбое целевой папки восстановления интеграции и постобработки. Исходный класс и XML прогона **10 тестов / 2 ожидаемых отказа** сохранены.

После исправления прошли **11 JVM-тестов**, без ошибок и пропусков:

- Реальные файловые ошибки целевого пути проверены при первой, средней и последней копии интеграции, а также при восстановлении постобработки.
- Отдельно внедрён `ENOSPC` после записи трёх байтов рабочей копии, для обоих этапов. Во всех случаях исходный checkpoint побайтно прежний, частичные рабочие файлы удалены, исключение сохраняет причину; повтор успешно восстанавливает точные прежние данные.
- Прежние проверки RGB16, проективных параметров, вложенной диагностики, повреждённых изображений/метаданных и изменившихся входов прошли. Повреждённый кэш не принят за пригодный.

Реальный диск не заполнялся. Тесты используют собственные временные каталоги и управляемую функцию копирования; обычный путь использует прежние `Files.copy` / `CheckpointFiles.copyAtomic`.
